GATE cloud is installed in namespace {{ .Release.Namespace }}.

Dagster UI (internal only):
  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ .Release.Name }}-dagster-webserver 3000:80

The sensor `asset_model_inputs_changed` syncs the asset model into ThingsFlow
({{ .Values.thingsflow.url }}) within a few minutes. It starts on its own; stop
it in the UI (Automation -> Sensors) to pause the sync.

The dashboard "GATE — Operación" (pages Overview, Analytics, Assets) is published
by `thingsflow_dashboard` as part of the same sync; it needs `weather_observations`
to have run once. Its template is the ConfigMap gate-cloud-dashboard, mounted at
/etc/gate-cloud/dashboard; change it in the chart (files/dashboard) and upgrade.

Schedules, all on by default (America/Toronto): `today_snapshot` every 15 min,
`weather_forecast` hourly at :05, `weather_observations` hourly at :10,
`circuit_daily_metrics` daily at 01:30 and `asset_twin_summary` nightly at 01:45.

After the first install, backfill `weather_observations` from HISTORY_START
(one run: single-run backfill), then `circuit_daily_metrics` over the same
days. `asset_twin_summary` runs nightly by itself and needs no backfill.

Upgrading from 0.3.0:
  - do not use --reuse-values; pass your overrides again (monitorDeviceId, the same
    dagster.postgresql.postgresqlPassword, -f values);
  - check `helm get values {{ .Release.Name }} -n {{ .Release.Namespace }}` first and do not
    override dagster.dagster-user-deployments.deployments (a list replaces the chart's,
    dropping the dashboard volume and GATE_DASHBOARD_PATH);
  - after the upgrade, materialise asset_twin_summary once (Assets -> asset_twin_summary
    -> Materialize) so Heatmap, Scatter, the 30-day bars and the 7-day columns fill
    before its nightly run at 01:45.

The Secret {{ .Values.thingsflow.existingSecret }} must hold THINGSFLOW_USERNAME
and THINGSFLOW_PASSWORD for the GATE tenant-admin account.
